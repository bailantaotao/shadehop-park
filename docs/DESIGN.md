# ShadeHop Park 設計文件

> 目標：讓帶小孩的爸媽快速找到「**現在**去不會曬、下雨也能玩」的公園，並知道車停哪裡。
> 同時讓 AI Agent 能搜尋到、而且拿到**可驗證、有出處、有時間戳**的正確資料。

---

## 1. 核心概念：把「遮蔽」拆成三種，而且其中一種會隨時間變

爸媽真正想問的是：「**我現在出門，到那邊時會不會曬到 / 淋到？**」
所以遮蔽不能只是一個「有 / 沒有」的標籤，而要分類型並和時間綁在一起。

| 等級 | 名稱 | 例子 | 遮陽 | 避雨 | 會隨時間變？ |
|---|---|---|---|---|---|
| **A** | 全天候遮蔽 | 高架道路 / 捷運高架下方、有屋頂的遊戲場 | ✅ | ✅ | 否（但側風雨、邊緣潑雨要註記） |
| **B** | 固定遮陽 | 遮陽帆、涼亭、棚架、成熟樹冠 | ✅ | ❌ / 部分 | 樹冠會隨季節變 |
| **C** | 建物陰影 | 被周邊大樓擋住太陽的公園 | ⏱️ 依時段 | ❌ | ✅ 依日期 + 時間 |

每座公園可以同時有多種遮蔽（例如遊戲區在高架下 = A，草皮區靠大樓 = C）。
因此**遮蔽是以「區域（zone）」為單位**，而不是以整座公園為單位。

### 1.1 A 級：高架下方

- 來源：OpenStreetMap 的 `bridge=*` / `layer` / `covered=yes`、`man_made=bridge` 多邊形與遊戲場多邊形做空間交集，初篩候選。
- **必須實地驗證**：高架下不一定真的是遊戲區、可能有施工圍籬。
- 額外欄位：淨高、是否有側邊潑雨、排水、噪音／空氣品質（車流）、照明。

### 1.2 B 級：遮陽設施與樹冠

- 遮陽帆、涼亭：實地照片 + 使用者回報。
- 樹冠：航照 / 衛星影像估算覆蓋率，標記「落葉季節會變少」。

### 1.3 C 級：建物陰影（技術重點）

用「建物 3D 模型 + 太陽位置」預先算出每座公園每個區域的**遮陰時刻表**。

```
輸入
 ├─ 建物輪廓 + 高度（國土測繪中心 3D 建物模型 / OSM building:levels / height）
 ├─ 公園遊戲區多邊形
 └─ 太陽方位角、高度角（依經緯度、日期、時間計算，例如 SunCalc / pvlib）

計算（離線批次）
 對每個 zone、每月代表日（或每週）、每 30 分鐘：
   1. 計算太陽向量
   2. 將周邊 300m 內建物投影出陰影多邊形（可用 pybdshadow 等工具）
   3. 陰影 ∩ zone 面積 / zone 面積 = 遮陰比例
   4. 疊加 A/B 級固定遮蔽

輸出
 shade_timetable[zone][month][time_slot] = 0.0 ~ 1.0
```

UI 呈現：每座公園一條「今日遮陰時間軸」，例如

```
08 09 10 11 12 13 14 15 16 17
██ ██ ▓▓ ░░ ░░ ░░ ▓▓ ██ ██ ██     █ 遮陰 >70%   ▓ 30–70%   ░ <30%
```

注意：
- 計算值是**模型推估**，必須標示 `method: "computed"` 和信心程度；有實地觀測時以觀測覆寫。
- 新建大樓會改變結果 → 建物資料更新時重算。
- 中午太陽高度角高（台灣夏季接近天頂），建物陰影幾乎消失，UI 應誠實顯示「中午無遮蔭」。

## 2. 爸媽真正在意的其他欄位

| 類別 | 欄位 |
|---|---|
| 遊戲設施 | 適合年齡（0–2 / 2–5 / 5–12）、共融設施、沙坑、戲水區 |
| 地面 | 材質（橡膠地墊在大太陽下會燙）、是否有積水問題 |
| 安全 | 是否有圍籬（防衝出馬路）、離車道距離 |
| 生活機能 | 廁所、親子廁所 / 尿布台、哺乳室、飲水機、洗手台、附近便利商店 |
| 可及性 | 推車友善、無障礙坡道 |
| 環境 | 蚊子多寡、噪音（高架下）、照明（傍晚） |
| **停車** | 最近停車場、步行距離、即時剩餘車位、收費、限高（休旅車）、路邊停車格 |

## 3. 停車資訊

- 資料來源：交通部 **TDX 運輸資料流通服務**（停車場基本資料 + 部分縣市即時剩餘車位）、各縣市政府開放資料、OSM `amenity=parking`。
- 每座公園預先算出步行 500m 內的停車場（用步行路網距離，不用直線距離），並依「步行到遊戲區」的距離排序。
- 即時車位：由後端代理 TDX API 並快取 1–2 分鐘；**回應中必須附上資料時間**，避免顯示過期資料。
- 額外：機車 / 推車下車點、是否有親子停車位、限高。

## 4. 使用情境與 UI

主畫面就是一個問題：**「現在要去哪玩？」**

- 預設篩選依當下天氣自動切換（串中央氣象署開放資料）：
  - 正在下雨或降雨機率高 → 只顯示 **A 級**
  - 晴天 / 紫外線高 → 顯示「**未來 2 小時**遮陰 ≥ 70%」的公園
- 時間滑桿：「我下午 3 點才會到」→ 地圖依 15:00 的遮陰重新著色。
- 篩選：下雨可玩、現在有遮陰、停車 ≤ 300m、有廁所、適合 0–2 歲。
- 公園卡片：遮陰時間軸、遮蔽類型、照片（含拍攝日期）、最近停車場與即時車位、**資料最後驗證日期**。
- 回報按鈕：「這裡現在其實很曬」「施工中」「設施壞了」→ 進入審核佇列。

## 5. 資料正確性（給人看、也給 AI 看）

正確性是這個產品的核心價值，也是 AI Agent 會不會引用的關鍵。

### 5.1 每個欄位都有出處

```json
"rain_cover": {
  "value": true,
  "method": "site_visit",          // site_visit | user_report | computed | official_data | satellite
  "source": "https://...",         // 官方資料或照片 URL
  "verified_at": "2026-09-30",
  "confidence": "high"             // high | medium | low
}
```

### 5.2 驗證流程

1. 自動匯入（官方開放資料、OSM）→ `confidence: low`
2. 衛星 / 計算佐證 → `medium`
3. 實地驗證（附照片、日期）或多位使用者一致回報 → `high`
4. 超過 6 個月未驗證 → 自動降級並標示「待確認」

### 5.3 資料用 Git 管理

- 每座公園一個 JSON 檔（`data/parks/<id>.json`），符合 `schema/park.schema.json`。
- 所有修改走 Pull Request → 天然的稽核紀錄、可回溯、可檢討。
- CI 驗證 schema、座標合理性、必填出處。

## 6. 讓 AI Agent 找得到、而且拿到正確資料

AI Agent 取得資料有三條路：**爬網頁**、**呼叫 API / 工具**、**下載資料集**。三條都要做。

### 6.1 網頁層（讓搜尋型 Agent 爬得到）

- **伺服器端產生的靜態頁面**（SSG），每座公園一個穩定網址：`/parks/<id>`。不要只靠前端 JS 渲染地圖。
- 每頁嵌入 **schema.org JSON-LD**（`Park` + `Playground`、`geo`、`amenityFeature`、`openingHoursSpecification`、`dateModified`）。
- 頁面上用**純文字**寫出關鍵事實，例如：「本遊戲場位於高架道路正下方，下雨可使用。最後實地驗證：2026-09-30。」
- `sitemap.xml`、`robots.txt` 明確允許主要 AI 爬蟲（GPTBot、ClaudeBot、PerplexityBot、Google-Extended 等）。
- `/llms.txt`：用 Markdown 告訴 LLM 這個網站是什麼、資料欄位意義、API 與資料集位置、引用方式。

JSON-LD 範例：

```json
{
  "@context": "https://schema.org",
  "@type": ["Park", "Playground"],
  "@id": "https://shadehop.example/parks/tpe-0001",
  "name": "（公園名稱）",
  "geo": { "@type": "GeoCoordinates", "latitude": 25.0, "longitude": 121.5 },
  "amenityFeature": [
    { "@type": "LocationFeatureSpecification", "name": "rain_cover", "value": true },
    { "@type": "LocationFeatureSpecification", "name": "shade_type", "value": "under_viaduct" },
    { "@type": "LocationFeatureSpecification", "name": "public_toilet", "value": true }
  ],
  "dateModified": "2026-09-30",
  "isAccessibleForFree": true
}
```

### 6.2 API + MCP Server（讓工具型 Agent 直接查詢）

- 公開 REST API，附 **OpenAPI** 規格（`/openapi.json`）。
- 提供 **MCP Server**，讓 Claude 等 Agent 直接呼叫工具：

| 工具 | 說明 |
|---|---|
| `search_parks(lat, lng, radius_m, at?, need_rain_cover?, min_shade?, filters?)` | 依位置、時間、遮蔽需求搜尋 |
| `get_park(id)` | 完整資料，含每個欄位的出處與驗證日期 |
| `get_shade_timeline(id, date)` | 指定日期的遮陰時間軸 |
| `get_nearby_parking(id)` | 附近停車場與即時車位（附資料時間） |

- 每個回應都包含：`as_of`、`source`、`confidence`、`url`（人可以點進去查證的頁面）。
  → Agent 可以回答「根據 ShadeHop（2026-09-30 實地驗證）…」，而不是瞎猜。
- 沒有資料時回 `null` + `reason`，**不要回猜測值**。

### 6.3 開放資料集

- 每日輸出 `parks.geojson`、`parks.csv`，附版本號與授權（建議 CC BY 4.0，回饋 OSM 社群相容可考慮 ODbL）。
- 可上架政府資料開放平臺 / Hugging Face Datasets，增加被引用機會。

## 7. 技術架構

```
           ┌──────────────── 離線批次（GitHub Actions，每日 / 每週）────────────────┐
官方資料 ─┐ │ 匯入 → 正規化 → 空間交集（高架/遊戲場）→ 建物陰影計算 → 停車場配對 → 驗證 │
OSM ──────┼▶│                     Python: geopandas, shapely, pybdshadow, pvlib       │
3D 建物 ──┘ └──────────────────────────────┬──────────────────────────────────────────┘
                                           ▼
                              data/parks/*.json（Git，PR 審核）
                                           ▼
           ┌───────────────────────────────┼─────────────────────────────┐
           ▼                               ▼                             ▼
   靜態網站 (Astro/Next SSG)       API + MCP Server（Edge）        開放資料集
   MapLibre GL + PMTiles          即時：TDX 停車、氣象署天氣      GeoJSON / CSV
   JSON-LD、sitemap、llms.txt      快取 1–2 分鐘
```

選擇理由：
- **靜態優先**：便宜、快、對爬蟲最友善；公園資料本身變動慢。
- **只有停車與天氣是即時**的，放在邊緣函式，其他全部預先計算。
- **MapLibre + PMTiles**：免費、無 Google Maps 授權問題，可離線。

## 8. 分階段

| 階段 | 範圍 | 驗收 |
|---|---|---|
| **MVP** | 單一城市（如台北）、只做 A 級高架下公園 + 停車場靜態資料、靜態頁 + JSON-LD + llms.txt | 30 座實地驗證過的公園 |
| **v1** | B 級遮陽設施、使用者回報、即時車位、天氣自動篩選 | 回報 → 審核 → 上線流程跑通 |
| **v2** | C 級建物陰影時刻表、時間滑桿、API + MCP Server | 計算值與實地觀測抽樣誤差 < 20% |
| **v3** | 擴展雙北 / 全台、開放資料集上架 | 被 AI Agent 引用可追蹤（referrer / API key 統計） |

MVP 先做 A 級的原因：最好驗證、最有差異化（「下雨也能放電」是爸媽最痛的點）、不需要複雜計算。

## 9. 風險

| 風險 | 對策 |
|---|---|
| 計算陰影不準 | 標示為推估、抽樣實測校正、使用者回報覆寫 |
| 資料過期（設施拆除、施工） | 驗證日期過期自動降級；回報機制 |
| 高架下空氣 / 噪音品質 | 誠實揭露，讓爸媽自己判斷 |
| 即時車位 API 不穩 | 顯示資料時間；失敗時退回靜態資料並標示 |
| AI 引用錯誤或過期資料 | 所有回應帶 `as_of` 與 URL；`llms.txt` 說明引用規則 |
